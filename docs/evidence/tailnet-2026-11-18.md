# Tailnet access — 2026-11-18

**Existing entry reused (not a new one):**

```
https://mac-mini.tail58d565.ts.net:8463  ->  http://127.0.0.1:11001   (tailnet only)
```

The serve entry was already correct. The app returned **403** for every request through it because `src/request-boundary.js` only trusts `localhost` origins. The iPhone was reaching the proxy and the proxy was reaching the server; the server was rejecting the phone's `Host`/`Origin`.

## Change

The server now runs with the existing external origin trusted:

```sh
PORT=11001 \
TERMINALONE_TRUSTED_ORIGINS=https://mac-mini.tail58d565.ts.net:8463 \
node src/server.js
```

Do **not** export `HOST` into the server environment. `src/server.js` already
defaults to `127.0.0.1`, but zsh treats an exported `HOST` as the machine name:
the PTY inherits it, `%m` renders `127`, and any host-dependent shell tooling
sees `127.0.0.1` instead of `Mac-mini.local`. The first restart leaked
`HOST=127.0.0.1` and produced the `floyd@127` prompt; the corrected restart
leaves `HOST` unset, and the prompt is `floyd@Mac-mini` again.

`scripts/install-service.sh` now writes `TERMINALONE_TRUSTED_ORIGINS` into the LaunchAgent when that variable is set, so a service install keeps tailnet access.

## Stale owner key after a server restart

The owner capability cookie and the browser workspace key are both minted per
server process. An open page therefore held a stale key after any restart and
repeated `Only the owner can create browser tabs.` on every click.

`public/workspace.mjs` now recovers: on an owner-auth 403 it re-fetches the
workspace key from `/api/browser/bootstrap`; if the owner cookie is also stale
it reloads once (15-second guard), and a user action that triggered the refusal
is stored and replayed after the reload. Background GET polls are not replayed.
`tests/owner-recovery.test.cjs` restarts the server under an open page and
asserts that a new browser tab is creatable and the restriction message is gone.
